## 🔴 Real correctness bugs (latent — current tests do not catch them)

- [x] **1. MPO silently drops every non-adjacent two-site term.** *(fixed v0.2.1, #78)*
  `finite_mpo.jl:162-196`. The FSM sets `W[done,done]=I` and `W[start,start]=I` but
  **never** `W[channel_k,channel_k]=I`, so a channel opened at site `i` cannot be
  carried to a partner at `j > i+1` — the term evaluates to **0**.
  **In scope per plan** (this is a genuine regression, not a deferred feature):
  - Part 2 §4 `BondTerm` (plan line 222): *"need not be nearest-neighbour; the
    generic pair also covers pairing (cc, c†c†)"*.
  - Part 2 §5 (lines 363/371): `two_point(g,dof,opA,iA,opB,iB)` is the *static*
    operator `AᵢBⱼ` whose expectation is an equal-time correlator, meant to be fed
    to `expect`/`MPO`.
  - Part 1 line 234 (Ex 6.x) & Part 2 line 508: long-range `ΣΣ SᶻᵢSᶻⱼ` is supposed
    to produce a **wider MPO**, not a zeroed-out term.
  - The `two_point` operator docstring (`operator.jl:421-473`) even uses sites
    `(1,4)` in its example and tells the user to evaluate via `MPO` → currently wrong.
  - Why tests miss it: the §9.1 cross-check uses the *exact* `two_point(ψ,…)` in
    `correlators.jl`, never the MPO path. Two code paths for "the same" observable,
    only one tested.
  - **Fix:** add `W[k+1,:,:,k+1] = Id` for the carry, and only open/close the channel
    at the matching endpoints.

- [x] **2. Periodic `Chain` emits `(L,1)` with `i>j`, which breaks every consumer.** *(guarded v0.2.2, #79)*
  `geometry.jl:100-107`. `dense_matrix` computes `middle = d^(j-i-1)` → `d^(negative)`
  for the wrap bond; `MPO`, `bond_hamiltonian`, `apply_gate` all assume `j=i+1`.
  **Nuance vs plan:** the `bonds` body matches the plan *verbatim* (Part 2 line 43:
  `g.periodic ? [(i, mod1(i+1,g.L)) for i in 1:g.L] : …`), and the plan calls periodic
  *"supported but discouraged"* (lines 36-38). So the bug is that "supported" is
  aspirational — the consumers silently misbehave on the wrap bond.
  **Fix:** either reject `periodic` in `dense_matrix`/`MPO`/TEBD with a clear error,
  or normalise the wrap bond and special-case it downstream.

- [x] **3. `entanglement_entropy` never normalizes `σᵢ²`.** *(fixed v0.2.3, #80)*
  `spectrum.jl:278-281` computes `−Σ σᵢ² log σᵢ²` on raw values. Correct for a
  `NoTrunc` canonical-centre bond, **wrong** on a truncated or non-canonical spectrum
  (Σσᵢ²≠1) — e.g. bond spectra straight out of TEBD. Plan agrees the formula is
  `−Σσᵢ²logσᵢ²` (Part 1 line 149) **but explicitly requires the centre at the bond**
  (line 529: *"free only when the canonical centre is at that bond"*). So calling it
  on raw TEBD `bond_svs` is outside the validity the plan states.
  **Fix:** normalize `p ./= sum(p)` (or assert `s.spectrum.normalized`).

## 🟠 Methodological caveats (exact for NoTrunc; sub-optimal otherwise)

- [ ] **4. TEBD truncates in a non-canonical gauge.** `tebd.jl:228-270`. `apply_gate`
  contracts the gate into the two local tensors and SVD-splits directly, without first
  bringing the MPS to mixed-canonical form centred on the bond. Consequences:
  (a) `NoTrunc` → exact, so the MBL / cross-check tests are valid; (b) with truncation
  the local SVD is **not** the global Schmidt decomposition, so discarded weight and the
  `bond_svs` stored at `tebd.jl:267` are not true Schmidt values, and truncation is
  non-optimal. The plan is aware centre placement matters (Part 1 line 529).
  **Fix (later):** canonicalise to `SiteCanonical(bond)`/`BondCanonical(bond)` before
  the gate SVD, or sweep a centre along with the gates.

## 🟡 Hallucinations & doc-vs-code mismatches

- [x] **5. `basis_change` referenced but not implemented.** *(docstring corrected v0.2.5, #82)*
  (`dense_matrix` warning). It *is* a planned Part 2 §3 function (plan line 205:
  *"MPO/physical_space/basis_change read it directly"*), just not built yet — so the
  advice is currently dead. Either implement it or soften the docstring to "planned".

- [x] **6. `power_method` shift condition is physically wrong.** *(docstring corrected v0.2.5, #83)*
  `power_method.jl:26-36, 113-116`. Says λ must exceed the *ground-state* energy `E₀`.
  For `(λI−H)` to be positive with `λ−E₀` dominant, λ must exceed the **largest**
  eigenvalue `E_max`. (The `Σ|couplings|` heuristic it also gives is the correct bound;
  the prose contradicts it.) Default `shift=4.0` is then risky for larger chains.
  Note: plan (Part 1 line 743) writes the iteration as `H − λI`; impl uses `λI − H`
  (negation) — both converge to the ground eigenvector when `λ > E_max`, so that sign
  flip is harmless; only the *prose* is wrong.

- [x] **7. `entanglement_spectrum` Bell-pair value is wrong.** *(docstring corrected v0.2.5, #84)*
  Claims `εᵢ = ln4` for `σ=1/√2`; actually `−2 ln(1/√2) = ln2`. Code is right, doc wrong.

- [x] **8. `apply_mpo` docstring describes a different algorithm than the code.** *(corrected v0.2.5, #86)*
  `finite_mpo.jl:294-297` says it "contracts to a full dense state vector first and
  then calls `to_mps`"; the code actually does a zip-contract + `_compress_thick_mps`.
  Pure hallucination — rewrite the docstring.

- [x] **9. `ed` time/full guard claim is false.** *(guard added to dense_matrix v0.2.4, docstring corrected v0.2.5, #85)* `ed.jl:292-294` says the `2^20`
  Hilbert-space guard is "checked by `sparse` internally", but `solve(:time)` and
  `solve(:full)` call `dense_matrix(H)`, which has **no** guard. Add the guard to
  `dense_matrix` or correct the docstring.

- [x] **10. `disorder.jl` Hamiltonian docstring double-counts the z-term.** *(corrected v0.2.5, #87)*
  `disorder.jl:55-59` writes `H = J Σ Sᵢ·Sᵢ₊₁ + Jz Σ SᶻSᶻ − Σ hᵢSᶻ` — the dot product
  already contains `SᶻSᶻ`. Actual `XXZ` is `J/2(flip-flop) + Jz SᶻSᶻ`. Fix the formula.

- [x] **11. `to_vidal` over-claims.** *(qualified v0.2.5, #88)* `vidal.jl:26`: *"`Γᵢ Λᵢ` recovers the
  right-canonical `Bᵢ`"* only holds if `Λ` are true Schmidt values; the left-sweep-only
  `bond_svs` it consumes generally aren't (same root cause as #4). The
  `to_vidal`/`to_canonical` round-trip is self-consistent, so this is doc-accuracy only.

## 🟢 Architectural deviations from the plan (work, but not as designed)

- [ ] **12. `bond_svs` type.** Plan wants `Vector{SchmidtSpectrum}` (Part 1 lines
  527-528, "the upgraded `bond_svs`"); implementation stores `Vector{SingValSpectrum}`.
  Consequence: bonds carry no `cut`/`center` location, and `entanglement_entropy` had to
  be defined on `SchmidtSpectrum` separately rather than `entanglement_entropy(ψ, bond)`
  (plan signature, line 517). Decide whether to upgrade now or record as deferred.

- [ ] **13. Power method bypasses the `solve` interface.** Plan wants
  `struct PowerMethod <: Algorithm` dispatched via `solve(H, GroundState(), pm)`
  (Part 1 lines 742-743); implementation exposes a free `power_method(H, ψ₀; …)`.
  Same for the absence of a `DMRG` algorithm. Unify under `solve` for consistency with
  ED/TEBD, or note as intentional.
