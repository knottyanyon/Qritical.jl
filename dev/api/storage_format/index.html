Storage Formats

A LatticeOperator is stored lazily as a list of OneSiteTerms and TwoSiteTerms over a geometry and DoF. Turning that term list into an actual matrix — via matrix_repr — can be done two ways, and the right choice depends entirely on what happens to the matrix afterwards:

  • A dense $d^L \times d^L$ array is convenient for full diagonalisation (LinearAlgebra.eigen) and for small systems where you want to inspect every entry.
  • A sparse SparseMatrixCSC avoids ever materialising the $d^{2L}$ zero entries of a nearest-neighbour Hamiltonian, which is essential once KrylovKit.eigsolve (or any other Lanczos/Krylov solver) is doing the work — those solvers only need matrix-vector products, never the full matrix.

Rather than have matrix_repr guess which one you want, the format is passed explicitly as a tag type — an instance of StorageFormat — so the choice is visible at the call site and dispatched on at compile time:

Hd = matrix_repr(H)                # defaults to DenseFormat()
Hs = matrix_repr(H, SparseFormat())

This mirrors the same "tag dispatch, not a Bool or Symbol flag" pattern used elsewhere in Qritical (e.g. TimeAxis, CanonicalRelation): adding a future backend — a BlockSparseFormat for TensorKit graded spaces carrying quantum number sectors, say — is a new subtype, not a change to every call site that already uses matrix_repr.

Types

Qritical.StorageFormat — Type
StorageFormat

Abstract supertype for matrix storage-format tags.

A StorageFormat tag is passed as the second argument to matrix_repr to select how a LatticeOperator is materialised into a concrete matrix:

  • DenseFormat — standard Julia Matrix{ComplexF64} (column-major dense array).
  • SparseFormat — SparseMatrixCSC{ComplexF64} from SparseArrays.

Future backends (e.g. BlockSparseFormat for TensorKit graded spaces carrying quantum-number sectors) will be added as new subtypes without changing existing code.

See also: matrix_repr, DenseFormat, SparseFormat

source
Qritical.DenseFormat — Type
DenseFormat <: StorageFormat

Storage-format tag requesting a dense Matrix{ComplexF64}.

Pass to matrix_repr to build the full $d^L \times d^L$ dense Hamiltonian matrix via Kronecker products. This is the default when no format is specified.

Practical limit: $d^L \lesssim 2^{20}$ ($L \approx 20$ for $d = 2$); larger systems exhaust memory.

See also: SparseFormat, matrix_repr

source
Qritical.SparseFormat — Type
SparseFormat <: StorageFormat

Storage-format tag requesting a sparse SparseMatrixCSC{ComplexF64}.

Pass to matrix_repr to assemble the Hamiltonian matrix using sparse Kronecker products. Suitable for Lanczos/Krylov solvers (KrylovKit.eigsolve) that only need matrix-vector products and never form the full dense matrix.

See also: DenseFormat, matrix_repr
